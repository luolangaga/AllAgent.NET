# LanAgent 作者档案

仅维护作者档案 `AUTHOR.md`，项目 `MEMORY.md` 已移除，不再读取、注入、自动总结或生成。

作者档案默认保存在 `%APPDATA%/LanAgent/AUTHOR.md`，终端通过共享目录配置选取位置，嵌入式宿主可设置 `AgentOptions.AuthorProfileDirectory`。

内容包括明确的技术偏好、GitHub 身份、已验证的电脑环境、缺失或不可用的工具及待确认事项。未知不代表缺失，不从仓库归属推断作者账号。

档案位于稳定系统提示词之后、所有对话消息之前，同轮工具迭代保持固定快照。轮末先由宿主筛选证据，仅在满足触发条件时进行一次作者档案总结，沿用作者档案工具卡片和历史恢复。

## 触发条件与频率

- 用户明确表达偏好、GitHub 等身份，或要求记住、纠正、删除档案内容：立即整理，可绕过环境更新冷却。
- 通过 `run_shell` 得到的常用开发工具版本、安装或缺失结果：先合并，默认累计 3 轮新的相关证据，或首条待整理证据满 10 分钟后，在下一轮结束时整理。一次工具调用不算一轮；重复输出不重复计数。
- 环境类整理请求之间至少间隔 10 分钟；失败也计入冷却，保留待整理证据供后续重试。明确的用户纠正无需等待。
- 普通聊天、助手自己的偏好描述、展开的文件引用不作为用户偏好来源。筛选使用本地中英文信号规则，不为每轮分类额外调用模型；未覆盖的表达可以通过“记住我的偏好”等明确措辞触发，最终是否有长期价值仍由总结模型判断。
- 无候选且无到期待办时，不调用总结模型、不展示空学习卡片；实际请求返回无新增时才显示“本轮无新增”。没有后台定时任务；无人继续对话时不发起请求。

`AgentOptions.AuthorProfileUpdateInterval` 和 `AuthorProfileBatchTurns` 分别控制冷却时间及合并轮数。显式调用 `AgentMemory.UpdateAsync` 时不传 `updatePolicy` 可直接整理，正常 Agent 运行会传入策略。

待整理证据与上次请求时间保存在共享作者目录的 `AUTHOR.pending.json`，在同一个作者文件锁内读写，可跨会话、跨进程继续合并。待整理正文最多 12000 字符、30 条，近期环境证据去重指纹最多 64 个；不保存完整会话。常见凭据标签及令牌形式会在入队前过滤。记录环境来源的电脑标识和检查时间，避免将旧检查结果当成本轮的新事实。

目标 1200 字符，硬上限 2000 字符；本轮证据最多 12000 字符、30 条消息；卡片最多 5 条、每条 120 字符。无新增不写文件，失败保留原档案。子代理、内部消息、取消和只读模式不自动更新。
