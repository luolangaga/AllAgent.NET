# Web 通讯、工具与流式展示修复（2026-10-18）

本次修改覆盖浏览器 `/web-ui` 与桌面 WebView 共用的桥接和会话逻辑，保留工作区中已有改动。

## 已修复的问题

| 问题 | 修复后的行为 |
|---|---|
| 审批和提问使用顶层通知，前端只认识流事件信封 | 同时接收两种消息，提问的 `id` 不会被当成 RPC 响应 ID |
| 提交失败先移除了提示，导致无法重试 | 后端确认后再移除；失败继续显示错误并允许重试 |
| 取消或其他页面答复后仍显示过期提示 | 后端广播 `interactions.resolved`，重连时重新读取权威待答列表 |
| 问题的多选字段被忽略，有选项时无法自由输入 | 支持多选及补充文字，按宿主协议提交 JSON 数组 |
| 初次连接失败后恢复连接却不重载页面数据 | 首次失败后的恢复也触发数据重载 |
| 连接队列包含已经拒绝或超时的写请求 | 断线、手动重连和超时均清理对应队列，避免旧操作在重连后再次执行 |
| 桥接请求可以无限等待，非法 JSON 可以导致空引用 | 请求超时和发送异常会明确失败；服务端验证请求格式并返回协议错误 |
| WebSocket 分片可能拆开中文或 emoji | 先收集完整消息字节，再进行一次 UTF-8 解码 |
| 外部网站可以尝试连接本地工具桥接 | WebSocket 握手校验 Origin；跨来源请求被拒绝 |
| 页面刷新或断线后失去正在运行的任务 | `chat.getStreamState` 返回活动运行快照，按事件序号补齐并去重，重新接收输出和停止操作 |
| 结束事件先于运行清理，紧接着发送下一轮会被拒绝 | 清理完成后发送终止事件，取消 RPC 等待通知和清理完成 |
| Web 执行绕过终端账号认证解析器 | 聊天、子 Agent、连接测试和模型列表均使用宿主认证及路由 |
| 消息对象原地修改，React 浅缓存阻止流式刷新 | 活动消息获得新引用，历史消息保留缓存 |
| 所有 store 共用订阅，每个 token 引发整页重算 | 按 store 隔离订阅，高频修改合并为约 16 ms 一次通知 |
| 全部工具堆在文字前面，看不出执行顺序 | 按事件顺序显示文字、工具和后续文字；保留完整文本用于复制 |
| 工具重复开始、缺少开始事件、结束后一直运行 | 按调用 ID 更新；保留孤立完成结果；终止时结算未完成工具 |
| 工具日志无限增长，stderr 无区别 | 前端保留最近 400 行并标记 stderr，取消与失败分别展示 |
| 折叠工具仍反复准备完整 JSON 和代码 | 只有展开后才格式化详情；PowerShell 源码按脚本展示 |
| 历史恢复修改原始缓存，正常工具仍带中断提示 | 使用独立视图投影；成功结果移除错误提示；容忍损坏记录 |
| 内部续写指令、展开后的文件正文被当作用户消息展示 | 使用可见历史，隐藏内部指令，优先显示原始 `InputText`，保留中断标记 |
| 无限步骤预算显示为 `第 n/0 步`，超时看起来像成功 | 显示实际步骤；明确展示超时、取消、上限和自动继续提示 |
| 固定名称入口脚本被缓存，更新后前后端版本混用 | JS、CSS、JSON 和入口 HTML 使用 `no-cache` |

## 验证

- 前端 Vitest：53 项，包含原有测试、通讯回归、断线恢复、事件去重、历史恢复，以及实际挂载 React 后连续 token 与工具状态的展示验证。
- 后端相关测试：WebUiBridgeTests、BridgeStreamJournalTests、AgentEngineTests、AgentQuestionTests、RuntimeModelSwitchTests、SubAgentIntegrationTests。覆盖真实 WebSocket 分片、Origin、审批取消、认证解析、生命周期及子 Agent 路径。
- 前端 `tsc --noEmit && vite build` 和桌面项目构建。
- 未主动向真实模型账号发送请求；账号路由测试使用测试 provider。

## 使用与边界

活动任务恢复要求原后端进程仍然存活。后端进程重启后可读取已持久化历史，已经终止的模型请求不会被重新执行。服务端活动事件日志在结束后释放；相邻文本事件合并，单个工具的实时输出保留最近 400 行。

验证时检测到已有 `allagent` 进程占用默认 Debug 输出的 DLL，因此后端测试使用独立 artifacts 目录完成，没有结束用户的运行进程。当前进程不会热更新 C# 代码。

关闭旧进程后，可从项目根目录执行 `./agent.ps1` 重新构建并启动，再运行 `/web-ui` 打开新版浏览器界面；桌面开发仍使用 `./dev.ps1`。

## 截图反馈的后续修复

- 红框的 `ask_user` 是违反 CodeAct 协议的直接调用尝试，没有执行。现在明确显示“调用格式错误 · 未执行”，并补充通过 `execute_code` 提问、读取回答后继续的示例。
- 每轮返回的思考内容分别放在对应文字和工具前。正在思考时自动展开，开始输出或执行工具时收起；已完成的思考可以手动重开。取消和失败结束当前思考状态。
- 事件快照保留时间戳，重连后仍能按轮恢复思考及其持续时间；历史记录按原有 assistant 消息恢复各轮内容，不制造模型未返回的思考。
- 普通终端启动仍默认不启动 WebUI。浏览器工作台和桌面端不再自动启动 MCP；新增配置默认停用，启用配置后仍需手动连接。
- 增加 MCP“断开”操作；停用、编辑和删除配置会等待连接释放，刷新页面读取实际连接状态。WebUI 独立管理 MCP，停止工作台时释放自身连接并保留终端连接。
- 此轮验证：58 项前端测试、53 项相关后端测试；包括真实 React 展开/收起行为和 MCP 子进程生命周期测试。
